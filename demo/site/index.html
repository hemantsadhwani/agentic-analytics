The monthly report

The same rule, on a schedule. A monthly review a manager can read in two minutes: headline numbers, what needs a decision, then the charts behind it.

  • Code draws every tile, bar and axis from the query rows.
  • "Needs a decision" rules are SQL in the report spec, reviewed like code.
  • The model writes the prose; every number in it is checked; a person approves before it is published.

How it works

  1. Understand in code. Product and place names are matched to exact values in the warehouse. Time words become exact dates, anchored on the data.
  2. Ask when unsure. "Sales" has two meanings here (online and resellers), so the bot asks. Unknown words stop the run before any model call.
  3. One read-only query. A schema graph links only the tables needed. The model writes one SELECT, which can read nothing else. Joins that would double-count are refused.
  4. Check, then answer. The filters must be in the SQL. Every number in the answer must match a cell the query returned. Product questions are answered from cited descriptions.
  5. Show the work. Each answer shows its SQL, its assumptions, the sources and the cost.
